## 4. Architecture

- **Data/config (M3, LIVE):** **`Assets/Data/Source/*.json` is the SINGLE SOURCE OF TRUTH** (cards/enemies/relics/potions/encounters/balance). ScriptableObject assets under `Assets/Data/<category>/` are GENERATED by the importer (menu `STS/重新匯入資料(JSON→SO)`) — hand-edits to SOs get overwritten on reimport; change the JSON instead. Importer updates SOs in place (GUID-preserving) and validates everything BEFORE writing (bad data aborts untouched). Known behavior: removing a JSON entry orphans its old .asset (dropped from GameDatabase but left on disk) — delete manually via editor if it matters.
- **Logic:** pure C# in `Assets/Scripts/Core/` (assembly `STS.Core`, `noEngineReferences: true` — it cannot touch UnityEngine, keep it that way; this is what makes it unit-testable).
- **Data assembly:** `Assets/Scripts/Data/` (`STS.Data`, pure .NET + precompiled Newtonsoft) — `ContentParser` (strict schema: unknown JSON fields = error; op/field combo whitelist; cross-reference checks) → `ParsedContent` → `ContentDb : IContentDb`.
- **Glue:** `Assets/Scripts/Game/` (`STS.Game`, engine refs allowed) — 7 SO types in `DataAssets/` mirroring the defs with 繁中 tooltips; `GameDatabaseAsset.BuildDb()` is the runtime entry (engine still sees only `IContentDb`). Editor-only importer lives in `Assets/Scripts/Game/Editor/` (`STS.Game.Editor`).

### Current Systems Map (verified against code 2026-08-03 — refresh via /harness-audit)

- **Combat math:** `STS.Core.Combat.CombatMath` — attack damage (strength add → weak ×0.75 → vulnerable ×1.5, float-multiply then single floor) + block absorption; `BlockMath` — block gain (dexterity add → frail ×0.75, floor). Damage/block modifiers live ONLY in these two classes; hooks must not become a second damage pipeline.
- **Combat engine (M1+M2, 2026-08-03):** `STS.Core.Combat.CombatEngine` — command-in/event-out (UI consumes the `CombatEvent` queue, never queries back mid-playback; `GetIntentPreview` is the ONLY sanctioned query, damage recomputed live), `CombatPhase` turn state machine incl. `AwaitingChoice` (card interrupts via `RequestChoice`/`ResolveChoice`), piles (hand cap 10, empty-pile reshuffle), energy incl. X-cost (`CostIsX`: spend-all, `XEnergySpent` feeds XEnergy/RepeatIsX), potions (`UsePotion`, shared EffectResolver). Block clears at the START of the owner's turn (test-locked). `EffectResolver` resolves all `EffectStep[]` ops except `Custom` (throws — deliberate escape hatch for M3+). Three damage paths ONLY: attack (CombatMath, fires Attack hooks), non-attack (block yes, modifiers no, NO hooks — thorns/SharpHide, prevents retaliation loops), direct hp loss (`LoseHp`, ignores block).
- **Hooks/Statuses/Relics (M2):** `HookBus` fires in deterministic order: player relics (acquisition) → player statuses (application) → enemy statuses; snapshots before iterating. 13 statuses in `StatusRegistry` (behavior in code, stacks in data); decay: timed debuffs -1 at OWNER's turn end, `JustApplied` skip only when applied during owner's OWN turn ([近似] StS semantics, test-locked). 10 relics in `RelicRegistry` (`RelicInstance.Counter` persists across combats — caller owns the instances).
- **Enemies (M2):** `EnemyDef`/`MoveDef` (moves = same EffectStep pipeline), `OpeningScript` then Loop/Weighted (`MaxConsecutive` reroll)/Custom AI; `GuardianAi` = mode-switch boss (damage threshold → defensive seq + SharpHide, then back). Next intent chosen right after the enemy acts (EnemyAi rng stream).
- **RNG:** `STS.Core.Rng.RngStream` (SplitMix64; deliberately a class, not struct — copy semantics would silently fork streams) + `RunRng` named streams (Map/CardReward/PotionReward/RelicReward/Shuffle/EnemyAi/CombatMisc). Determinism is the testing backbone; never use System.Random.
- **Cards:** `STS.Core.Cards` — `CardDef` (upgrade = separate def, id convention `strike`/`strike+`), `CardInstance` (InstanceId for UI tracking), `EffectStep` (flat op schema, maps 1:1 to future JSON). `STS.Core.Content.IContentDb` is the only content lookup the engine sees.
- **Feel/Perf (M7, 2026-08-28):** hit-feel pass — enemy hit flash+punch (`EnemyView.PlayHitFeedback`), attack lunge, death shrink, player HUD shake, tuned beats; all tweens follow DOTween discipline (DOKill-then-tween, SetLink). Perf baseline recorded in verify skill 管道4 (avg 8.58ms / worst 38.47ms / GC ~2.6MB/s during auto-run combat; regression thresholds defined). **Bulk numeric calibration of [近似] values deliberately deferred: it happens by user-supplied data table → edit JSON → reimport, zero code.** Known deferred polish: targeting arrow is a straight line; need-target potions auto-pick first living enemy; hand rebuild (not pooled).
- **Run UI (M6, 2026-08-28):** full-loop screens in `STS.Game.UI` — MapScreenController (node graph + edges + reachable pulse + ScrollRect + run HUD), Reward/Shop/Rest/EndScreenController, DeckViewOverlay (view/pick modes, self-destroying). **Router+action-hub pattern: `GameController` owns ALL screen actions (`EnterNodeFromMap`/`RewardTakeCard`/`ShopLeave`/`RestHealAction`…) — screen buttons call these game-level methods, and the full-run smoke (`煙霧_啟動自動一輪`, writes `Temp/STS_RunSmoke.txt`) walks the SAME methods.** Combat hands back via `CombatScreenController.OnCombatEnded` callback; used potions synced to RunState by before/after diff; combat overlay widgets live under a self-destroyed container (no orphans on screen switch). **`Application.runInBackground = true` is set in Awake — without it an unfocused editor freezes play-mode frames and automated smoke silently hangs (paid-for lesson).**
- **UI (M4, 2026-08-27):** code-built uGUI — the scene (`Assets/Scenes/Main.unity`, generated by menu `STS/建置主場景`) holds ONLY GameRoot(`GameController`)+EventSystem(`InputSystemUIInputModule`)+camera; ALL widgets are constructed at runtime by `STS.Game.UI.*` via `UiKit` (placeholder art = colored `Image` + TMP text; deliberate for the pre-art phase — art phase will introduce prefabs). `CombatScreenController` is the ONLY class touching the engine: command in, then plays the `CombatEvent` queue with beats, input locked during playback (`InputEnabled`). `GameController` self-heals null refs from Resources (`Assets/Data/Resources/GameDatabase.asset`, `Assets/Fonts/Resources/NotoSansTC SDF.asset`) — scene wiring is optional. Smoke hook: `CombatScreenController.煙霧_出第一張可出的牌()`.
- **Fonts/TMP:** TMP Essentials imported (`Assets/TextMesh Pro/`); 繁中 font = Noto Sans TC (OFL, `Assets/Fonts/NotoSansTC-Regular.otf`) with dynamic TMP asset generated by menu `STS/生成 TMP 繁中字型資產`. `UiKit.MainFont` is injected by GameController at Awake.
- **DOTween asmdef fact:** DOTween UI-module shortcuts (`DOAnchorPos`/`CanvasGroup.DOFade`…) live in loose Module sources — an asmdef-isolated assembly CANNOT see them until `Assets/Plugins/Demigiant/DOTween/Modules/DOTween.Modules.asmdef` exists (generated via DOTween Utility Panel → Create ASMDEF, user-clicked 2026-08-27); `STS.Game` references `DOTween.Modules`. Do not delete that asmdef.
- **Map/Run (M5, 2026-08-27):** `STS.Core.Map.MapGenerator` — grid paths bottom-up (±1 col, merge-on-collision, NO crossing — all structural params in BalanceDef), fixed rows (0=Combat, mid=Treasure, last=Rest, virtual Boss node), weighted types with min-row constraints; Map rng stream only, seed-locked by tests. `STS.Core.Run.RunEngine` — `NewRun` (starting loadout from BalanceDef), `EnterNode` (rolls contents AT entry), encounter pools (weak first N normal fights), `ApplyCombatResult` (rewards: gold/card-3-pick/potion drop with ±delta floating chance/elite relic), shop (buy card/relic/potion, remove service with escalating cost), rest (heal %/upgrade). Combat itself stays in CombatEngine; Run only assembles `CombatSetup` and writes back results. `IContentCatalog` (extends IContentDb) is the Run layer's full-catalog view — engine still sees only IContentDb.

## 8. Working Protocol for the AI

1. **Plan first (in Traditional Chinese)** — approach, which dependencies apply, which files change.
2. **Check §2 triggers** — Input System for input, URP for rendering, C# only for logic; UI work requires settling §2.1 first.
3. **Confirm before large refactors.** Single-file edits and additive features proceed directly.
4. **Finish the job.** No TODO, no stubs.
5. **If unsure, say so.** Do not fabricate API signatures — verify against installed source or `unity_reflect`.
6. **Verify before "done".** Follow `.claude/skills/verify/`: compile check is mandatory after any code change; EditMode tests after logic changes; play-mode smoke + log scan after behavior/scene changes; report evidence tiers ([驗證]/[推論]/[假設]); never report completion without evidence.
7. **Pure logic goes to STS.Core with tests** — copying the CombatMath + CombatMathTests pattern is the default for rules/calculations/state machines.
